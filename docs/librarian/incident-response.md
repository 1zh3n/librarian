# Librarian 事故响应

日期：2026-11-23
适用：公网部署的入口、账号、数据、AI 和 MCP 事故。目标是先止损，再取证，最后恢复。

## 1. 立即判断

| 症状 | 首步 |
| --- | --- |
| 入口被扫描/暴力登录 | Cloudflare 限流和 WAF 拦截；检查登录审计；必要时临时关闭入口 |
| 账号疑似失陷 | 撤销该账号全部会话和 MCP grant；重置密码和 MFA；检查写入/分享/发布记录 |
| 文档被误公开 | 撤销分享和发布；检查 Cloudflare 缓存和静态站；保留访问日志 |
| AI/MCP 外发敏感内容 | 关闭该 Workspace 的外部 AI/MCP；撤销 grant；保留任务和工具调用审计 |
| 主机疑似失陷 | 隔离主机（快照、断网、停 Caddy）；不要在原机继续操作 |
| 备份损坏/丢失 | 从异地 restic 或离线归档恢复；核对 SQLite 和 Git 历史 |

## 2. 入口止损

```bash
# 临时只允许管理地址访问，或直接停 Caddy
systemctl stop caddy

# 保留应用运行但阻断公网入口时，优先在 Cloudflare 侧关闭代理/防火墙规则
```

- 不要把“停应用”当成唯一止损：会话、分享链接、MCP grant 和发布目标都要分别撤销。
- 保留 Cloudflare 日志、Caddy 日志、journald、数据根快照；不要在取证前重建主机。

## 3. 账号与会话

- 撤销受影响账号的全部浏览器会话。
- 撤销该账号的 MCP grant 和 CLI 投递令牌。
- 重置密码；重置 MFA；检查是否新增管理员或成员。
- 检查该账号最近的写入、分享、发布、备份和 AI 任务。

## 4. 数据与分享

- 撤销匿名分享链接；确认固定版本链接没有继续读取新内容。
- 撤销发布目标或停止 Zola 构建；清理 CDN/静态站缓存。
- 检查 `backup-targets.json`、`publication-targets.json` 和 `.librarian/` 下的凭证文件。
- 如果凭证进入过文档或备份，先撤销凭证，再评估历史、备份和外部目标的清理范围。

## 5. 主机与凭证

按顺序轮换：

1. Cloudflare API token、Origin CA 私钥、Authenticated Origin Pulls 证书；
2. SSH 主机密钥和管理员密钥；
3. Librarian 管理员密码、会话签名材料、MCP client 凭证；
4. AI 供应商密钥、Git 备份密钥、restic 密码；
5. 任何写入过 `/etc/librarian/` 或数据根的部署秘密。

从已知干净的发行包重建主机，使用升级前/事发前备份恢复数据，再重新开放入口。不要从被入侵的主机复制二进制。

## 6. 恢复顺序

1. 在隔离网络启动新主机和 Librarian，只监听回环。
2. 用 `restore.sh` 或 restic 恢复数据根；核对 SQLite、账号、文档、版本和附件。
3. 轮换所有凭证后再启动 Caddy 和 Cloudflare 入口。
4. 先允许管理员登录，验证权限、审计和撤销；再恢复普通成员。
5. 观察 24 小时登录失败、5xx、429、备份和外发记录。

## 7. 记录

事故记录至少包括：发现时间、影响范围、止损动作、涉及账号/空间、外发渠道、恢复点、轮换的凭证、遗留风险和复核时间。不要把正文、token 或分享凭证写入事故记录。

## 8. 联系与演练

- 指定一名事故负责人和一名备份联系人；上线前填入实际联系方式。
- 每季度做一次桌面演练：账号失陷、分享误发、备份损坏各一次。
- 每次演练后更新本文件和 [公网部署运行手册](public-deployment.md)。
